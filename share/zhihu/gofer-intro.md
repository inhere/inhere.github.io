## 标题

同时开好几个 Claude Code / Codex 会话，怎么管住它们改了什么？

## 正文

用 coding agent 久了，单个会话好用，开到三四个就开始乱：哪个在等我回复，哪个已经改完了，改的东西有没有跑过测试，昨晚派出去的任务是做完了还是半路报错退出了。我自己的情况更麻烦一点，会话分在两台电脑和一个容器里。

下面说说我试过的几种办法，最后是我自己写的一个工具。

### 1. 先把「改了什么」隔离开

最有用的一步是让每个任务在自己的 git worktree 和分支里干活。主目录不动，几个 agent 同时改同一个仓库也不会互相踩，改坏了直接删分支。代价是合并时可能冲突，但冲突至少是显式的。

### 2. 「做完」和「验收通过」分开

agent 说做完了，不等于做完了。我的做法是让任务结束后停在「待验收」，把它的汇报、提交、diff、测试输出放在一起看，再决定合并还是打回。打回时带上理由，让它在原来的会话里继续改，不用重新交代上下文。

### 3. 等人拍板的事放到一个队列里

会话停下来问「要不要继续」「选哪个方案」，如果只能在终端里看到，人一离开电脑就卡住了。我把这些都汇到一个页面：待批准的任务、待回答的问题、待验收的结果、等回复的会话，手机浏览器上也能处理。

### 4. 我自己的做法：gofer

上面这些我做成了一个工具叫 gofer（我是作者）。单个 Go 二进制带 Web 控制台，MIT 开源，自己部署：

- 一台机器跑 server，其他电脑或容器作为 worker 主动连上来，不用开入站端口；
- 任务可以派给 Claude Code、Codex、ACP agent 或普通命令，它不带模型，只是启动和管住你已经装好的 CLI；
- 终端里正在开的会话也能登记进来，停下来时在网页上回复或唤醒。

它不是沙箱，适合个人或互相信任的小团队。还在 0.x，接口会变。
