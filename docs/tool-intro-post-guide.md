# 工具 / 项目介绍文章：写作要点与结构

适用于介绍自己写的工具、库、应用的文章（例如 `gofer-intro`、`suga-long-session`）。纯技术复盘、踩坑记录不必套这个结构。

来源：2026-10-27 对照几篇知名工具的发布文章（Astral 的 uv、Tailscale 的 How Tailscale works、Simon Willison 的 LLM 命令行工具）重排 `gofer-intro`，以及 2026-10-26 suga / miglite 分发的结果；2026-11-13 按 `apic-intro` 的定稿修订（开头直接写能力、去掉第一人称和过程 / 局限 / 预告板块）。

## 1. 读者只看第一屏

从社区帖子点进来的人，多数只看第一屏就决定走不走。第一屏要回答：这是什么、能做什么、怎么用起来。

- **第一句直接写工具和核心能力。** 「`apic` 是一个……的工具：**一句话定位**」，不要用「我每天要……」这类个人场景开头（2026-11 的 suga、apic 初稿都这样写，没人看）。定位加粗，文章、README、各站草稿用同一句。
- **紧跟三四条核心能力。** 每条一个加粗短标题加一句说明，写具体能力（命令、选项、支持的类型），不写形容词。
- **`<!-- more -->` 放在能力列表之后。** 列表页摘要显示的就是定位加能力列表。
- **然后马上是基本信息和上手。** 许可证、交付形态、平台一两句，接仓库 / 发布页链接，再接「快速安装」「快速开始」两节（各一个代码块，四五条命令），让读者先跑起来。
- **演示放在上手之后。** 一条有代表性的命令和它的输出（或动图），再接详细用法。

不要放在第一屏的：

- 个人场景铺垫、「先交代清楚」「免责声明」式的开场。
- 和标题重复的海报。海报做分享卡片（front matter `extra.social_media_card`），在社交平台转发时显示，正文里不再放。
- 架构图、组件清单。读者还没看到用法时，抽象结构读不进去。

## 2. 推荐结构

1. 一句话定位 + 三四条核心能力，然后 `<!-- more -->`
2. 基本信息一句 + 仓库 / 发布页链接
3. **快速安装**、**快速开始**：可直接复制的命令
4. **演示**：一条代表性命令和输出
5. **核心用法**：一个最常用的流程从头走到尾，命令配一两句解释
6. **第二、三个亮点**：各一节，每节一个具体场景 + 少量命令或一张截图
7. **它是什么、不是什么**：适用范围、明确不做什么
8. **和同类工具比**（可作为上一节的小节）：先说对方的长处，再说自己的取舍

不写的板块：「怎么做出来的」（开发过程、提交数、AI 参与）、「局限」、「接下来 / 下一批」、结尾预告和「欢迎 star」。这些读者不看，放进发布说明或 README。

## 3. 写法

- **不用第一人称。** 全文不出现「我」，用工具作主语（「apic 会……」），或直接写命令。
- **具体胜过形容。** 用命令、截图、数字说话；「强大」「优雅」「革命性」一律不用。
- **对比要公道。** 每个同类工具先写一句它真正的优点；不点名贬低。
- **AI 参与不进正文。** 社区要求披露时，在那个站点的帖子里按版规写；禁止 AI 内容的社区不发。
- **命令可直接复制。** 占位符统一用 `<project>`、`<server>` 这种写法；不出现个人路径、内网地址、真实 token。
- **中英两篇信息一致**，只有语言差异；英文稿不用破折号、不用 "actually" 这类口头禅（见 humanizer）。
- **图片**：演示动图中英各一份（界面语言跟文章一致）；手机截图用 `<img ... width="320">` 控制宽度；每张图写清 alt。

## 4. 分发时的经验（2026-10-26 / 27）

写社区草稿前读 `share/AGENTS.md` 与 `share/community-sharing.md`，另外注意：

- **不要同一天铺多个站、多个项目。** 2026-10-26 一天里把 miglite、suga、eget 发到 HN、r/golang、Go Forum：HN 两篇自荐被标 flagged，r/golang 被删，Go Forum 被标 spam、博客域名被拦。一次发一两个站，间隔两三天，每个帖子都回复评论。
- **Show HN 要能直接试用**：贴仓库，不贴博客文章；账号先有正常参与记录再自荐。
- **规则以浏览器里看到的现行版规为准**，发前核对 flair、AI 披露要求、是否只允许链接帖（r/selfhosted 旧版规要求只贴链接、标题与文章标题一致）。
- **中文策展渠道**：HelloGitHub（issue 自荐）、阮一峰《科技爱好者周刊》（issue 自荐）收录后能带来集中的关注，可以早投。
- **全文同步站**（掘金、dev.to、Hashnode、Medium）没有门槛，canonical 指回本站原文。
- **README 第一屏同样重要**：仓库链接出现在每篇草稿里，README 也按第 1 节的思路排（一句话 → 动图 → 三四条要点 → 五行以内的快速上手）。
