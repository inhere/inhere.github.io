# 工具 / 项目介绍文章：写作要点与结构

适用于介绍自己写的工具、库、应用的文章（例如 `gofer-intro`、`suga-long-session`）。纯技术复盘、踩坑记录不必套这个结构。

来源：2026-10-27 对照几篇知名工具的发布文章（Astral 的 uv、Tailscale 的 How Tailscale works、Simon Willison 的 LLM 命令行工具）重排 `gofer-intro`，以及 2026-10-26 suga / miglite 分发的结果。

## 1. 读者只看第一屏

从社区帖子点进来的人，多数只看第一屏就决定走不走。第一屏要回答三件事：这是什么、跟我有什么关系、它真的能用。

- **第一段讲场景，不讲产品。** 用一个读者自己也遇到过的具体处境开头（「同时开着三四个 agent 会话……经常答不上这几个问题」），比「X 是一个……的工具」更能让人读下去。
- **第二段给一句话定位。** 加粗，一句话。推广用的定位要先定稿，文章、README、各站草稿用同一句。
- **紧跟着放最有说服力的东西。** 能演示的放动图（操作全过程，十几秒），能量化的放对比图。它要出现在 `<!-- more -->` 之前，这样列表页摘要里也能看到。
- **基本信息一小段就够。** 许可证、交付形态（单个二进制 / 自带控制台）、当前版本和稳定性（`0.x`、接口可能变），一两句话；并告诉读者安装步骤在哪（「文末『试一下』，五条命令左右」）。
- **紧接着放仓库和发布页链接。**

不要放在第一屏的：

- 「先交代清楚」「免责声明」式的开场。必要的说明放进基本信息那一句，或放到「局限」。
- 和标题重复的海报。海报做分享卡片（front matter `extra.social_media_card`），在社交平台转发时显示，正文里不再放。
- 架构图、组件清单。读者还没看到用法时，抽象结构读不进去。

## 2. 推荐结构

1. 开场场景 + 一句话定位 + 演示动图（第一屏）
2. 基本信息一句 + 仓库 / 发布页链接
3. **核心用法**：一个最常用的流程从头走到尾，命令配一两句解释（「一个任务长什么样」）
4. **第二、三个亮点**：各一节，每节一个具体场景 + 少量命令或一张截图（「多台机器」「手机上接会话」）
5. **它是什么、不是什么**：组成部分、适用范围、明确不做什么（不是沙箱、不做多租户……）
6. **更多能力的预告**：一段列表，标明后续文章会展开
7. **可信度**：怎么做出来的、用了多久、真实数据（提交数、版本数、任务数，含失败数）
8. **和同类工具比**：先说对方的长处，再说自己的取舍和代价
9. **局限**：平台支持、安全边界、文档完成度，照实写
10. **试一下**：完整的安装和启动命令，链接到详细上手指南
11. **结尾**：接下来写什么，加一个真实的问题或反馈渠道。不写「欢迎 star」

顺序的原则：先让读者看到「它能为我做什么」，再讲「它是怎么组成的」。

## 3. 写法

- **具体胜过形容。** 用命令、截图、数字说话；「强大」「优雅」「革命性」一律不用。
- **数字要可核对。** 写明取数日期和口径；失败数照写，比只写成功数可信。
- **对比要公道。** 每个同类工具先写一句它真正的优点；不点名贬低。
- **AI 参与要如实写。** 代码主要由 agent 编写的，写清楚人负责什么（拆任务、审 diff、跑测试、发版）。不要回避，也不要在禁止 AI 内容的社区发。
- **命令可直接复制。** 占位符统一用 `<project>`、`<server>` 这种写法；不出现个人路径、内网地址、真实 token。
- **中英两篇信息一致**，只有语言差异；英文稿不用破折号、不用 "actually" 这类口头禅（见 humanizer）。
- **图片**：演示动图中英各一份（界面语言跟文章一致）；手机截图用 `<img ... width="320">` 控制宽度；每张图写清 alt。

## 4. 分发时的经验（2026-10-26 / 27）

写社区草稿前读 `share/AGENTS.md` 与 `share/community-sharing.md`，另外注意：

- **不要同一天铺多个站、多个项目。** 2026-10-26 一天里把 miglite、suga、eget 发到 HN、r/golang、Go Forum：HN 两篇自荐被标 flagged，r/golang 被删，Go Forum 被标 spam、博客域名被拦。一次发一两个站，间隔两三天，每个帖子都回复评论。
- **Show HN 要能直接试用**：贴仓库，不贴博客文章；账号先有正常参与记录再自荐。
- **规则以浏览器里看到的现行版规为准**，发前核对 flair、AI 披露要求、是否只允许链接帖（r/selfhosted 旧版规要求只贴链接、标题与文章标题一致）。
- **中文策展渠道**：HelloGitHub（issue 自荐）、阮一峰《科技爱好者周刊》（issue 自荐）收录后能带来集中的关注，可以早投。
- **全文同步站**（掘金、dev.to、Hashnode、Medium）没有门槛，canonical 指回本站原文。
- **README 第一屏同样重要**：仓库链接出现在每篇草稿里，README 也按第 1 节的思路排（一句话 → 动图 → 三四条要点 → 五行以内的快速上手）。
